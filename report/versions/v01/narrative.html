01

The question

Chain-of-thought monitoring assumes that reasoning a model does not write down, it cannot do. That assumption has a name and a bound: opaque serial depth, the length of the longest computation a model can perform without interpretable intermediate steps. Brown-Cohen, Lindner & Shah derive it architecturally — an upper bound on what the network permits, computed from the weights.

An upper bound only constrains the worst case. What a trained model actually achieves is an empirical question, and the gap between the two is where monitoring risk really lives. This pilot measures the realized quantity behaviorally, and asks a second question the architectural bound predicts but does not test: when latent computation fails, does it fail because the work is deep, or merely because there is a lot of it?

02

A task where depth is the only variable

Every trial shows the model a randomly generated mapping table — a single cycle over two-letter codes — and asks a question answerable only by looking codes up in it. The table is regenerated per trial, so nothing is memorizable, and its lines are shuffled so reading order reveals no structure.

Two task families use the same table and require the same number of lookups. They differ in one respect: whether the lookups depend on each other.

The serial task requires k steps that cannot be reordered or overlapped: hop two needs hop one's answer. The parallel task requires the same k lookups, but all of them can happen at once, followed by a single aggregation — depth 2 regardless of how large k grows. Difficulty in raw work is matched; only the shape of the computation differs.

Three conditions

Immediate forces an answer with no reasoning: the assistant turn is prefilled with Answer:, generation is capped at 8 tokens, and provider-side hidden reasoning is disabled. Filler appends 100 counting tokens before that same forced answer, following the filler-token literature. CoT lets the model reason freely, establishing that the task is solvable at all.

Compliance was near-perfect: across all forced-answer trials, — leaked visible reasoning, and CoT accuracy stayed at or near ceiling through k=8 for five of six models — so any collapse in the immediate condition is a limit on unwritten computation, not on task comprehension.

03

The answers are wrong in a specific way

Scoring an answer right or wrong throws away most of what the model reveals. Because the mapping is a cycle, every code sits at a known distance from the start, so a wrong answer can be located: it is the code n hops along. This turns each response into a reading of how far the model actually travelled.

Wrong answers are almost never random. Responses land on the cycle essentially always, and their distance from the start tracks the request. At low k they systematically land too far.

A natural objection: perhaps the models simply read "follow the mapping twice" with different fencepost semantics than intended. A control condition rewrote the prompt to spell the counting out explicitly — following it once gives the code X maps to; following it twice gives the code that code maps to — and changed nothing.

What this measures

The mean landing position keeps climbing well after accuracy has collapsed. On a 32-code table, Claude Opus 4.5 asked for 8 hops answers correctly 15% of the time but lands 13.3 hops out on average. Substantial latent traversal is happening; what fails is control over where it stops.

04

Depth is the constraint, not work

This is the experiment the architectural bound predicts. Same table, same number of lookups, same answer format — chained versus independent. If the collapse were about how much work a forward pass can hold, both should fail together. If it is about serial depth, only the chained version should fail.

Filler tokens moved nothing consistently — effects averaged within a few points of zero in both directions, with no reliable sign. At 100 tokens on these tasks, there is no evidence that filler raises serial depth, which is what the theory predicts; there is also no clear width benefit, so this reads as a null rather than a confirmation. Published filler uplift used longer sequences and problem repeats, which this pilot has not yet tested.

05

Where width finally breaks

If parallel work survives eight lookups, how far does it go? A final sweep pushed both task families to 24 lookups on a fixed 32-code table, so table size is held constant and only the number of required lookups varies.

06

What this does and does not show

The headline is a shape claim, and it is clean: at matched work on a matched table, latent computation is limited by serial depth, not by volume. A model that cannot chain three lookups silently can perform twenty in parallel. For chain-of-thought monitoring, that is the reassuring half — genuinely sequential hidden reasoning is expensive for the model, and the architectural upper bound is far from saturated.

The unreassuring half is the landing-position result. Accuracy scores the stopping point, and stopping is exactly what these models are bad at; traversal itself runs considerably deeper. A monitoring argument built on accuracy-based hop ceilings is measuring the wrong quantity, and will understate how much sequential computation is available.

Limits

  • Elicitation-dependent. These are lower bounds under one prompting scheme. Better elicitation, or training pressure to hide reasoning, could raise them; nothing here is a safety guarantee.
  • One task family. Chained symbol lookup is contamination-proof and cleanly depth-parameterized, but it is not natural reasoning. Whether the same ceiling governs multi-hop factual or mathematical reasoning is untested here.
  • The parallel comparison is not perfectly matched. The parallel prompts list k codes, so they run slightly longer than the serial prompts at the same k, and the aggregation step is a task component the serial version lacks.
  • Filler is a null, not a refutation. Only one filler type at one length was tested.
  • GPT-5.1's CoT baseline never reached ceiling (50% at k=8), so its immediate-condition numbers should not be read as a depth measurement until that is understood.

What would sharpen it next

  • Longer filler and problem repeats, against the published uplift settings.
  • Landing-position readings on natural multi-hop facts, where prior work reports a ceiling near four hops using accuracy alone.
  • Calibrating hops against the architectural bound: how many layers does one latent hop consume, and how much of the permitted depth goes unused?
